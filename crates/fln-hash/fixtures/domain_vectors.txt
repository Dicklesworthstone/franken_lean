# schema fln-domain-vectors/1
# format: domain|tag|digest_empty|digest_abc|digest_zeros1024|digest_pattern2049
#
# WHAT THESE FREEZE (bead franken_lean-rps): the domain-separation layer, not BLAKE3.
# Every row pins one registered Domain's derive_key context string together with the
# digests it produces. The registry's central claim is that a tag is frozen forever once
# shipped — changing one changes every declaration hash, cache key, receipt and logical
# root in the program, which is an epoch-class event and never a refactor. Before this
# fixture existed nothing enforced that: the domain tests checked pairwise distinctness
# and tag uniqueness, all of which survive editing a tag string.
#
# EVIDENCE CLASS — read this before citing these numbers. They are REGRESSION vectors
# generated by this implementation, not independent conformance vectors. They cannot and
# do not testify that our BLAKE3 is correct; that claim rests entirely on
# blake3_vectors.txt, which carries the official upstream test vectors and is what the
# L2 spec-vectors rows in ci/PARITY_LEDGER.txt point at. The chain is: the core is
# verified against upstream, and this fixture freezes the domain layer built on it
# against silent drift. Cross-platform identity remains unearned until CI supplies
# certified-matrix hosts — these vectors were produced on one host.
#
# INPUTS. digest_empty is the zero-length input. digest_abc is the three ASCII bytes
# "abc". digest_zeros1024 is 1024 zero bytes — exactly one BLAKE3 chunk, so it lands on
# the chunk boundary. digest_pattern2049 is 2049 bytes of the repeating pattern
# 0,1,...,250,0,1,... (modulus 251, the same sequence the official vectors use), which
# crosses two chunk boundaries and therefore exercises the parent/tree path rather than
# only the single-chunk path.
